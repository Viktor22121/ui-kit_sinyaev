# ATLAS UI Kit — практическая работа № 5

## Запуск
Из папки проекта выполните `python -m http.server 5500` и откройте http://localhost:5500.

## Исходная проблема и план
В стартовом проекте не было тёмной темы, переключателя, состояний кнопок, полей и уведомлений. Страница использовала токены лишь частично. План: тёмные роли в `tokens.css`, затем логика темы в `theme.js`, компоненты в `components.css`, плотность и предупреждение, проверка на всех ширинах.

При диагностике в DevTools (Elements → Computed) цвет фона первой кнопки равен `rgb(24, 83, 164)`, источник: `--button-bg-primary` → `--color-primary` → `--base-blue-700`.

## Архитектура токенов
Три уровня: примитивы `--base-*` и шкалы, семантические роли `--color-*`, компонентные `--button-*`, `--control-*`, `--alert-*`. Компоненты обращаются к компонентным токенам и ролям, HEX есть только в `css/tokens.css`.

- Заливка primary-кнопки: `--base-blue-700 → --color-primary → --button-bg-primary → .button--primary { background }`
- Текст primary-кнопки: `--base-white → --color-on-primary → --button-text-primary → .button--primary { color }`
- Подпись secondary-кнопки: `--base-slate-950 → --color-text → --button-text-secondary → .button--secondary { color }`
- Отступ поля: `--space-4 → --control-padding-inline → .input { padding }`

## Темы и плотность
| Режим | Как определяется | Ключ localStorage |
|---|---|---|
| Системная (auto) | Нет `data-theme`, действует `prefers-color-scheme` | `atlas-theme` = `auto` |
| Светлая, тёмная | `data-theme` на `<html>`, приоритет над ОС | `atlas-theme` |
| Компактная | `data-density="compact"` на `<html>` | `atlas-density` |

В компактном режиме переопределены: `--button-height`, `--control-height`, `--button-padding-inline`, `--control-padding-inline`, `--component-gap`, `--alert-padding`, `--alert-gap`.

## Ответы на вопросы
**Почему плотность задаётся компонентными токенами?** Плотность касается размеров конкретных компонентов, а не смысла цветов или общей шкалы отступов. Переопределив --button-height и --control-height на корне, мы меняем все кнопки и поля одним блоком, не копируя стили .button и .input. Шкала --space-* при этом остаётся неизменной и не ломает остальную страницу.

**Почему тёмная тема не должна хранить прямые цвета внутри .button?** Тогда кнопка знала бы о теме сама: каждый новый компонент и состояние требовали бы своего тёмного правила, и значения быстро разошлись бы. Сейчас тема переопределяет роли на :root, а .button получает их через токены, поэтому тёмная тема и смена фирменного цвета выполняются в одном месте без правки компонента.

## Что отличается от PNG-ориентира
- В ориентире тёмной темы вторичная кнопка светлая и с низким контрастом надписи; здесь она тёмная, с видимой границей, контраст подписи 11,68:1.
- Недоступная кнопка нейтрального цвета, а не бледно-синего: так она не похожа на активное действие.
